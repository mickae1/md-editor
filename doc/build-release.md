# Build and release

## Three ways to run

| Mode | Workstation requirements | Launch |
|---|---|---|
| Sources | Python 3.10+, Edge | `pythonw mdeditor.pyw [folder]`; shortcut via `install-shortcut.ps1` |
| Development | Python, Node | `python server/app.py sample/Help/Md --port 8765 --no-window` + `npm run dev` in `web/` |
| Compiled | Edge only | `release/mdEditor/mdEditor.exe [folder]` |

In sources mode, the server serves `web/dist`: **this folder is versioned** and must be rebuilt (`npm run build`) and committed after every change to `web/src`. `node_modules` is not needed on the workstations.

## `build.py`

```
pip install pyinstaller      # build machine only
python build.py              # npm ci if needed, npm run build, then PyInstaller
python build.py --skip-web   # reuses web/dist
```

- Generates `build/mdEditor.spec`: two `Analysis` (`mdeditor.pyw` with `web/dist` → `web` and `lang/` → `lang`, and `server/mcp_server.py` without tkinter), two `EXE`, a single `COLLECT`.
- **Folder mode**: `mdEditor.exe` (no console) and `mdeditor-mcp.exe` (console, stdio) and `mdeditor-cli.exe` (console, exports) share `_internal/` (Python, libraries, UI, `_internal/lang`). Nothing is unpacked at startup (startup ≈ 0.5 s).
- Copies `README.md`, `CHANGELOG.md`, `LICENSE` and `installer/install.ps1` / `uninstall.ps1` into the folder, and produces `release/mdEditor-<VERSION>-windows.zip`.
- `build/` and `release/` are ignored by git.

In the executable, `server/app.py` detects `sys.frozen` and reads the UI from `_MEIPASS/web` instead of `web/dist`, and the language files from `_MEIPASS/lang`.

## Version

`VERSION` in `build.py`, `version` in `web/package.json`, `SERVER_INFO` in `server/mcp_server.py` and `server_version` of the `Handler`: update them together, and add the version to `CHANGELOG.md` (move the *Unreleased* items under it, with the date).

## Pre-release checklist

1. `cd web && npm run typecheck && npm test && npm run build`
2. `python server/test_mcp.py` and `python server/test_toc.py`
3. `lang/*.json`: same keys in every bundled language file.
4. End-to-end test on a copy of `sample/Help` (see `CLAUDE.md`).
5. `python build.py --skip-web`, then `MDEDITOR_MCP_EXE=release/mdEditor/mdeditor-mcp.exe python server/test_mcp.py`.
6. Run `release/mdEditor/mdEditor.exe sample/Help/Md` and check that it opens.
7. Test `release/mdEditor/install.ps1` with `-Destination <temp> -NoPath -ShortcutFolders <temp>`, then its `uninstall.ps1`.
8. Update `CHANGELOG.md` (version, date).

If a corporate antivirus flags the executables: allow-list them or sign them with a company certificate.

## Icons

`assets/icon.svg` is the source; `assets/mdeditor.ico` is generated by `node tests/make-icon.mjs`, run from `web/` (Edge capture via playwright-core).

## Exporting

`server/export.py` (used by the UI, `/api/export`, and by `server/cli.py`, which is `mdeditor-cli.exe`):

- **Website**: `mkdocs build -f - --no-directory-urls --site-dir <out>`, so each page keeps the name of its `.md` file.
  - The configuration is given on standard input: `INHERIT: mkdocs.yml` plus a `nav` built from the table of contents. MkDocs runs in the folder of `mkdocs.yml`, so relative paths (`docs_dir`, `pymdownx.snippets.base_path`) work as in the normal build, and nothing is written into the documentation folder.
  - A **Contents** page is generated after the build, from a built page used as a template: `contents.html`, or `index.html` without `index.md`. It is the first entry of the `nav`.
  - The output folder must be empty, be the `site_dir` of `mkdocs.yml`, or contain a previous export (`.mdeditor-export` marker), because MkDocs empties it first. The documentation folder, its parents and its subfolders are refused.
- **PDF**: the website is built into a temporary folder, its pages (`<article>`) are gathered in the order of the table of contents, with ids and links scoped per page, and Edge headless prints them (`--print-to-pdf`). The contents are on the first page, then one page per topic.
- **MkDocs command**: `mkdocs_command()` in `server/app.py` uses `MDEDITOR_MKDOCS` (a `mkdocs.exe` or the `python.exe` of an environment with MkDocs), else the running Python (sources), else `mkdocs` / `python` from `PATH` (compiled).

`python server/test_export.py` runs the real builds when MkDocs is available. For example, with a throwaway environment:

```
python -m venv %TEMP%\mkvenv && %TEMP%\mkvenv\Scripts\pip install mkdocs-material
set MDEDITOR_MKDOCS=%TEMP%\mkvenv\Scripts\python.exe
python server/test_export.py
```

## Installer (`installer/`)

`install.ps1` runs from the unzipped release folder, for the current user and without administrator rights:

1. copies the folder to `%LOCALAPPDATA%\Programs\mdEditor` (`-Destination`). A previous installation is replaced as a whole. A non-empty folder without `mdEditor.exe` is refused, and so is a running mdEditor;
2. creates the shortcuts (`-NoShortcuts`, `-ShortcutFolders`);
3. adds the folder to the user `PATH` (`-NoPath`), read and written raw (`REG_EXPAND_SZ`) so that `%VARIABLES%` stay unexpanded;
4. with `-Mcp`: runs `claude mcp add --scope user mdeditor -- <mdeditor-mcp.exe> [--root ...]`, and adds `mcpServers.mdeditor` to `%APPDATA%\Claude\claude_desktop_config.json` (backup `.bak`, other entries kept).

Everything done is written to `install.json`, which `uninstall.ps1` reads to undo exactly that (`-KeepFiles`, `-RemoveSettings`). The scripts are ASCII and target Windows PowerShell 5.1. In a string, write `${name}:` rather than `$name:`, which is parsed as a drive.

To test without touching the real environment, use a fake release folder with `-Destination <temp> -NoPath -ShortcutFolders <temp>`, and `APPDATA=<temp>` for `-Mcp`, with `claude` out of the `PATH`.
