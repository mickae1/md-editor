# Interface languages

The interface text lives in language files, so it can be translated or corrected without rebuilding. Server and MCP messages are English only.

## Language files

`lang/<code>.json`: a flat JSON object, one entry per text. The file name is the language code (`en`, `fr`, `de`...).

```json
{
  "@name": "Français",
  "workspace.saved": "Enregistré : {name}",
  "store.usedBy": "utilisé par {n} topics",
  "store.usedBy.one": "utilisé par 1 topic"
}
```

- `@name`: language name shown in the menu.
- `{name}`: placeholder, filled by the code. Keep the same placeholders as in `en.json`, but you can move them.
- `<key>.one`: optional singular form, used when the `n` placeholder is 1.
- A missing key falls back to English. An unknown key is ignored.
- UTF-8 (a BOM is accepted).

`lang/en.json` is the reference: it defines every key, and it is bundled into the interface as the fallback. `lang/fr.json` is shipped too.

## Where the files are loaded from

`server/app.py` (`LANG_DIRS`, `load_languages`) reads these folders in order. A later file overrides an earlier one **key by key**, so a custom file only needs to contain the texts it changes:

1. `lang/` of the application (bundled into `_internal/lang` in the executable);
2. `lang\` next to `mdEditor.exe` (compiled version only), for a company-wide translation;
3. `%APPDATA%\mdEditor\lang\`, per user. The menu item *Open custom language folder...* creates and opens it.

A new code (for example `de.json`) adds a language to the menu.

## Choosing the language

The theme menu (top right) lists *Automatic* and every language found. The choice is saved as `language` in `%APPDATA%\mdEditor\settings.json` and the window reloads.
*Automatic* uses the browser's `Accept-Language` header (the Windows language), or English if no file matches (`pick_language`).

At startup, `web/src/boot.ts` calls `GET /api/i18n`, installs the texts (`setMessages`), then imports `main.ts`. The language stays fixed while the page is open, so `t()` can also be called when a module loads.

## In the code

```ts
import { t } from '../i18n'

toast(t('workspace.saved', { name: basename(doc.path) }), 'success')
h('span', null, t('store.usedBy', { n: users.length }))
```

- Never hard-code user-visible text in `web/src`. This covers labels, tooltips, placeholders, dialogs and toasts.
- Key = `<area>.<camelCaseName>`. The area is the source file name (`workspace`, `views`, `image`...) or a shared group (`dialogs.ok`, `lang.*`).
- Use placeholders instead of string concatenation, so that translators can reorder words.
- `MessageKey` is derived from `lang/en.json`: an unknown key fails `npm run typecheck`.

Adding a text: add the key to `lang/en.json` **and** `lang/fr.json`, then call `t()`.
`npm test` runs `web/tests/lang.test.ts`, which checks that:
- every `lang/*.json` file has exactly the keys of `en.json`, with the same placeholders;
- every `t('...')` key used in `web/src` exists.

Adding a bundled language: copy `lang/en.json` to `lang/<code>.json`, translate the values, change `@name`, then run `npm test`.
